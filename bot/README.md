# VK-бот для выдачи прокси

Приложение на `@verse-bot/vk` из проекта `verse-bot`. Использует опубликованный пакет `0.1.0`: соседний репозиторий на сервере не требуется. Работает через Long Poll, без входящих портов.

## Запуск на сервере прокси

### Установка скриптом (рекомендуется)

На VPS нужны Git, Docker Engine с Compose и `flock` (util-linux). Запускайте от пользователя, у которого проекты лежат в `~/projects` и есть доступ к Docker, без `sudo` перед скриптом.

После публикации файлов в `main`:

```bash
curl -fsSL https://raw.githubusercontent.com/vdistortion/mtproto-web-proxy-manager/main/bot/deploy.sh -o /tmp/mtproxy-bot-install.sh
bash /tmp/mtproxy-bot-install.sh install
```

Скрипт клонирует репозиторий в `~/projects/mtproxy-manager-bot` и создаст `bot/.env`. Заполните его, затем повторите:

```bash
bash ~/projects/mtproxy-manager-bot/bot/deploy.sh install
```

Обновление без GitHub Actions — одна команда:

```bash
bash ~/projects/mtproxy-manager-bot/bot/deploy.sh update
```

Она получает изменения `main`, обновляет только fast-forward, собирает образ и пересоздаёт контейнер. `.env` и volume с привязками сохраняются. Локальные изменения исходников останавливают обновление. Параллельные запуски блокируются. Каталог и ветку можно переопределить через `BOT_INSTALL_DIR` и `BOT_BRANCH` (указывайте те же значения при обновлении).

При ошибке сборки работающий контейнер сохраняется. Ошибка запуска нового контейнера не вызывает автоматического отката; проверьте `docker compose logs --tail=50 bot` из каталога `~/projects/mtproxy-manager-bot/bot`. `--wait` проверяет запуск контейнера, но не успешность доставки сообщения через VK.

### Автоматическое обновление через GitHub Actions

После первой установки добавьте в GitHub Settings → Environments → `production` secrets:

| Secret            | Значение                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------- |
| `VPS_HOST`        | Адрес VPS                                                                                   |
| `VPS_USER`        | Пользователь, установивший бот                                                              |
| `VPS_PORT`        | SSH-порт, необязательно (22 по умолчанию)                                                   |
| `VPS_SSH_KEY`     | Приватный ключ для входа; публичную часть добавьте в `~/.ssh/authorized_keys` на VPS        |
| `VPS_KNOWN_HOSTS` | Проверенная запись ключа сервера из `known_hosts`; для нестандартного порта — `[host]:port` |

Workflow `Deploy VK bot` запускает тесты и обновление по SSH при изменениях `bot/` в `main`; также доступен ручной Run workflow для `main`. На VPS используется тот же `deploy.sh update` и стандартный каталог `~/projects/mtproxy-manager-bot`. Обновляется актуальный `main` на момент запуска. Для приватного репозитория отдельно настройте на VPS доступ Git к origin; SSH-ключ Actions нужен для входа на VPS, а не для скачивания репозитория.

Токен VK остаётся в `.env` на VPS и не нужен в GitHub Secrets. Если Actions не настроен, пользуйтесь ручной командой обновления выше.

### Настройка VK и ручной запуск из репозитория

1. В сообществе VK включите сообщения и Bot Long Poll API с событием `message_new`. Создайте токен сообщества с доступом к сообщениям.
2. Из корня репозитория:

   ```bash
   cd bot
   cp .env.example .env
   chmod 600 .env
   ```

3. Заполните `.env`: `VK_TOKEN`, положительный числовой `VK_GROUP_ID`, ваш числовой `VK_ADMIN_IDS` (несколько через запятую). `PROXY_CONFIG_DIR` — каталог менеджера, по умолчанию `/etc/mtproto-manager`.
4. Запустите:

   ```bash
   docker compose up -d --build
   docker compose logs --tail=50 bot
   ```

Каталог конфигурации монтируется целиком только для чтения, чтобы бот видел атомарные замены файлов менеджером. Docker socket не подключается. Контейнер использует root для чтения конфигурации менеджера с правами `700/600`.

Привязки находятся в `bindings.json` в постоянном volume `bot-data`. Перезапуск и пересборка их сохраняют. `docker compose down -v` удаляет привязки. Резервная копия:

```bash
docker compose cp bot:/data/bindings.json ./bindings.backup.json
chmod 600 bindings.backup.json
```

Для восстановления остановите бот, выполните `docker compose cp ./bindings.backup.json bot:/data/bindings.json`, затем `docker compose start bot`.

## Использование

Непривязанным аккаунтам бот не отвечает ни на сообщения, ни на команды. Заранее получите числовой VK ID пользователя отдельно и отправьте боту в личке:

```text
/bind 123456789 alice
```

`alice` должен уже существовать в менеджере и быть активным. Повторный `/bind` заменяет привязку. Пользователь отправляет `/tg` или нажимает «Мои прокси» и получает четыре ссылки: WEB, WEB (dd), MTProxy (ee), MTProxy (dd). `/start` показывает подсказку и клавиатуру.

После привязки пользователь отправляет первое сообщение (например, `/start`) — в ответ появляется клавиатура: «Мои прокси», «О данных», «Отвязать аккаунт». Сам `/bind` не отправляет пользователю уведомление. Администраторы из `VK_ADMIN_IDS` могут пользоваться ботом без собственной привязки.

Несколько VK ID могут быть привязаны к одному имени: `/bind 123456789 alice` и `/bind 987654321 alice`. Каждая связь независима.

### Самостоятельная отвязка и данные

- `/privacy` или «О данных» — какие данные получает и хранит бот, доступ администратора и роль VK как канала передачи сообщений.
- `/unlink` или «Отвязать аккаунт» — запрос на удаление связи с текущим VK ID. Подтверждение: `/unlink confirm` или «Подтвердить отвязку» в течение двух минут. `/cancel` или «Отмена» отменяет запрос. Перезапуск бота или повторная административная привязка отменяет ожидающее подтверждение.
- После подтверждения связь удаляется из постоянного хранилища, клавиатура скрывается, и бот перестаёт отвечать этому аккаунту. Исключение — администраторы, чьи права задаются отдельно в `VK_ADMIN_IDS`. Другие аккаунты того же пользователя продолжают работать. Повторная привязка выполняется администратором.

Отвязка не отзывает уже выданные ссылки и не удаляет переписку в VK или копии данных из резервных копий. Для отключения самих ссылок нужно обратиться к администратору. При восстановлении старой резервной копии привязки также могут восстановиться.

### Административная отвязка

```text
/unbind 123456789
```

Удаляет только привязку VK. Для отключения уже полученных ссылок используйте `sudo mtproto-manager block-user alice`.

Команды работают только в личке. Администраторы определяются исключительно по `VK_ADMIN_IDS`. Конфигурация перечитывается при запросе: удалённые и заблокированные пользователи ссылок не получают. Смена домена/порта отражается сразу. Привязка содержит отпечаток секрета: после пересоздания пользователя или смены секрета нужен повторный `/bind`. Разблокировка с прежним секретом восстанавливает выдачу автоматически.

## Локальный запуск

Нужен Node.js 22.9+ (рекомендуется 24). Код и тесты написаны на TypeScript 7.0.2 со строгой проверкой типов. Укажите доступный каталог конфигурации в `.env`:

```bash
npm ci
npm run typecheck
npm test
npm start
```

Привязки хранятся в `BOT_DATA_DIR` (по умолчанию `./data`). Запускайте один экземпляр на токен и хранилище. Приложение не журналирует тексты сообщений, токены и ссылки. Ошибки чтения не сбрасывают привязки.

`npm run build` компилирует приложение и тесты в `dist/`; `npm test` сначала выполняет эту сборку. После изменений исходников пересоберите проект перед `npm start`. В Docker сборка выполняется отдельным этапом, в итоговый образ попадают только скомпилированное приложение и runtime-зависимости. Workflow проверяет компиляцию вместе с тестами.
